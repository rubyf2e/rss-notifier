### Postman

以 Backend 實際 contract 修正：

`postman/rss-notifier-api.postman_collection.json`

確保：

- endpoint path 與 Controller 完全一致
- HTTP method 一致
- auth 設定一致
- request body 一致
- query parameters 一致
- path parameters 一致
- response assertions 不再驗證過時格式
- pagination response 依目前 Backend contract 驗證：
  - `items`
  - `page`
  - `limit`
  - `total`
  - `totalPages`
- success status assertions 與 Backend 一致
- error cases 的 status / response assertions 與 Backend 一致

目前已知要特別確認：

```text
GET /subscriptions
```

目前 Backend 是：

```json
{
  "items": [],
  "page": 1,
  "limit": 20,
  "total": 0,
  "totalPages": 0
}
```

不要再讓 Postman 把 response 當成單純 array。

另外確認目前實際 endpoint 是否為：

```text
PATCH /subscriptions/:publicId/pause
PATCH /subscriptions/:publicId/resume
DELETE /subscriptions/:publicId
GET /subscriptions/unsubscribe
```

以 Backend 實際 Controller 為準，不要依舊文件猜測。

### 文件原則

- 以 Backend 實際 contract 為最終來源。
- Postman example / tests 用來驗證與呈現實際 API。
- 不把 Postman 舊內容當成 API contract。
- 不自行發明 endpoint、欄位、status code 或 error message。
- Backend 與 Postman 不一致時，以 Backend 為準並修正 Postman。
- `api.md` 最後依修正後的 Backend + Postman 同步更新。
- 不需要保留「Postman / Backend 差異」段落來描述已修正的差異。
- 若仍存在無法由 Backend 確認的內容，明確標示，而不是猜測。

### Validation

不要修改 Backend。

檢查：

1. Postman JSON 格式有效。
2. Collection 中所有 endpoint 都能對應目前 Backend Controller。
3. Postman request / assertions 與 Backend contract 一致。
4. `api.md` 與 Postman、Backend 一致。
5. 不存在過時的 endpoint、response schema、pagination assertion。

如果有可用的 Postman CLI / collection runner，執行相關 collection tests；否則至少進行 JSON / contract 靜態檢查。
